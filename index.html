Teaching Claude to Connect

Part 1 gave Claude memory, but memory without hands is just a journal. MCP servers give Claude hands — direct access to your CRM, your code, your docs, and your channels.

9 servers, 120+ tools, one protocol, and a case study where the standard integration path didn't exist — so we built around it.

The Problem

Smart but Isolated

After Part 1, Claude remembers everything — your corrections, your architecture decisions, your product naming rules. But when you ask it to pull up the Roblox account, or check what's in Slack, or look at that PR, it can't, because none of that lives in memory.

🔒

No CRM Access

Ask "what does Roblox own?" and you're on your own, looking it up in Salesforce, navigating across multiple account variants, screenshotting the asset page, pasting it into the conversation, and hoping Claude reads the formatting correctly.

🔌

No Code Context

Say "review that PR" and you copy the diff, paste it, and lose half of it to context-window limits, so Claude ends up reviewing a fragment without ever seeing the repo.

🔇

No Communication

Say "send the follow-up to the customer" and it stops there, because Claude drafts the email and then you copy it, open Slack, paste it, fix the formatting, and send it yourself.

The tax is invisible, but it adds up. Every time you Alt-Tab to look something up and paste it back, you're burning 30-60 seconds and cluttering the context window with raw, unstructured data, so do that 20 times in a session and you've lost 10-20 minutes, plus 30% of your context window spent on copy-paste artifacts instead of real work.

The Protocol

MCP in 30 Seconds

Model Context Protocol is an open standard from Anthropic that lets Claude call external tools such as APIs, databases, CLIs, and browsers through one standardized interface. Think of it as USB-C for AI, where a single protocol carries any capability.

P

Protocol

A JSON-RPC standard that lets any host, whether Claude Code, Cursor, or Windsurf, speak the same language to any server.

S

Server

A lightweight wrapper around an API, CLI, or service that runs locally or remotely and exposes the tools Claude can call.

T

Tool

A single capability such as "search Slack," "read a PR," or "query CRM," which Claude decides when to call and you either approve or auto-allow.

Case Study

The Impossible Connection

Salesforce's corporate CRM (Org62) holds everything — pipeline, contacts, contracts, installed products, consumption data. It's the single source of truth for every deal.

We needed it inside Claude, but getting a Connected App in Org62 requires a business technology review that doesn't scale to individual SE projects.

The Constraint

×
No Connected App in Org62

You can't create one, because it requires internal IT approval that doesn't exist for individual SE tooling, which kills JWT Bearer Flow dead.

×
No API credentials

There's no client_id, no client_secret, and no certificate, so the standard OAuth patterns are all off the table.

×
No direct middleware connection

Our Cloud Run middleware can't query Org62 either — no JWT, no OAuth, no cert, just a hard wall between production infra and the corporate CRM.

The Solution — sf CLI + MCP

✓
Salesforce CLI authenticated locally

sf org login web --alias org62 is a browser-based SSO login that uses your existing corporate credentials, with no app registration needed.

✓
MCP server wraps sf CLI commands

A custom Node.js MCP server that calls sf data query --query "SELECT..." --target-org org62 under the hood. Claude calls the tool, the server runs the CLI.

✓
Cache-forward architecture for production

MCP gathers the data and pushes it to a middleware cache (Redis 4h / Cloud SQL 24h), and every production entry point (LWC, Agentforce, Slack) reads from that cache, so you fix it in one place and it's available everywhere.

New Addition

Slack MCP — The Second Data Plane

The newest server in the stack, and it turned out to matter more than expected. Claude can now search Slack, read channels and threads, send messages, and create canvases, but the real value is in what it surfaces, the unstructured human signal that no CRM captures.

What It Unlocks

  • • Search across channels — find that conversation about a deal strategy from last week without scrolling
  • • Read thread context — Claude can follow a thread to understand the full discussion before drafting a response
  • • Send messages — draft and post directly. Meeting follow-ups, deal updates, team announcements
  • • Create canvases — publish long-form content like this very post series, formatted and ready to share

  // Claude calls slack_search_users("Sarah")
  // Claude calls slack_search_channels("acme-deal")

  // Claude calls slack_send_message (DM)

Architectural Insight

Two Data Planes, One Account

After authenticating to corporate Slack, I wondered whether Slack MCP made the Meridian CRM tools redundant — if I can search Slack for "Roblox," why query Org62 separately?

I tested it, and the answer is a definitive no, for a reason that reveals something important about how MCP servers compose.

💬

Slack MCP

Unstructured, conversational, and full of human signal.
What it returns for "Roblox"
  • • Team dynamics — who's working the deal, who's the AE, who's looped in on technical
  • • Competitive intel — mentions of competing platforms, win/loss context from deal channels
  • • Customer sentiment — how the customer reacted in meetings, what concerns were raised
  • • Risk signals — executive changes, project delays, escalations flagged by the team
This is the story, the context, the human judgment layer.
📊

Meridian MCP (Org62)

Structured and quantitative, the system of record.
What it returns for "Roblox"
  • • Installed products — exact SKUs, quantities, per-unit pricing, discount percentages, contract periods
  • • Deal history — every won, lost, and open opportunity with amounts and close dates
  • • Account variants — multi-org customers appear as separate CRM accounts (core, Slack, Tableau)
  • • Consumption health — CCR utilization, contract values, renewal timelines
These are the numbers, the contracts, the single source of truth.

The Architectural Insight

MCP servers don't need to talk to each other, or even know the others exist. Claude is the integration layer — it decides which servers to call and synthesizes the results.

Think of it like Unix pipes, where each MCP server is a specialized command (grep, sort, awk) and the LLM is the pipe operator | that chains them into composability without coupling.

A compound query across both planes

A real workflow where Claude calls 3 MCP servers to build a complete picture.
me: Prep me for my Roblox meeting tomorrow. What do they own, what's the team saying, and what's in the news?
  // Claude calls crm_asset_lines("Roblox") → Meridian MCP
  // Claude calls slack_search_public("Roblox") → Slack MCP
  // Claude calls v4_news("Roblox") → Meridian MCP (v4)
claude: Here's your prep. Roblox owns Sales + Service Cloud, Data Cloud, Event Monitoring, and Tableau across 2 account variants. Slack shows the AE flagged a competitive evaluation last week, and GDELT news says they just announced a partnership with...
  // Three data sources, one synthesized answer, zero tab switches.
Build Your Own

Start with 3 Servers in 15 Minutes

You don't need 9 servers on day one — start with the three that deliver the most value for SE work, then add more as you need them.

1

GitHub — Code access (2 minutes)

claude mcp add github --scope user -- npx -y @modelcontextprotocol/server-github

PR reviews, issue management, and code search, once you set GITHUB_PERSONAL_ACCESS_TOKEN in the env.

2

Context7 — Up-to-date docs (1 minute)

claude mcp add context7 --scope user https://mcp.context7.com/mcp

Current library docs for any framework, on a free tier with no API key needed, which fixes the "stale training data" problem for technical work.

3

Slack — Communication (5 minutes)

claude mcp add slack --scope user -- npx -y @anthropic/slack-mcp

Search, read, and send messages, which needs a Slack bot token carrying the channels:history, chat:write, and search:read scopes, then set SLACK_BOT_TOKEN.

+

Level Up — Build a Custom Server

Once you see the pattern, you can wrap any API, and our Meridian server is ~400 lines of Node.js, where each tool is a function that takes params, calls an API, and returns JSON, while the MCP SDK handles the protocol.

If your team has internal APIs, dashboards, or data sources that Claude should access — a custom MCP server is 2-4 hours of work for a developer who's seen the pattern.
